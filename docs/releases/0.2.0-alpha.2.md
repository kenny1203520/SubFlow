## Required publishing stages

1. Check exact tag, package/lockfile versions and a single dated, nonempty changelog section.
2. Run full Go tests/vet and vulnerability scans, frontend tests/build, release contract tests and every Playwright project.
3. Build the production image. In a separate uninitialized container, exercise setup, registration, failed/successful login, admin permissions, direct reload, About version and audited logout.
4. Rehearse Alpha 1 data upgrade and offline backup restore with isolated volumes. Check financial amounts/IDs, groups, attachment bytes, legacy notification backfill and idempotent restart.
5. Publish the versioned image and GitHub pre-release with changelog and immutable image reference.
6. Compare actual registry/release outputs and ensure alpha leaves stable latest unchanged. Any unsuccessful stage fails the final outcome.

After successful publication, merge back into develop through [PR #47](https://github.com/kenny1203520/SubFlow/pull/47). No alpha is merged into master. Never move a published tag to repair a workflow.

## Safety and remaining scope

The upgrade rehearsal uses disposable generated data, not a backup of a user's installation. Before upgrading real data, stop writes and retain the full PocketBase directory and the same SUBFLOW_SETTINGS_ENCRYPTION_KEY. Restore a backup into a separate directory with the old image; do not run an old binary over an upgraded live schema.

SMTP qualification uses a real TCP server on loopback. External provider credentials, TLS policy and inbox deliverability require deployment-specific checks. Broader group-role permutations, several edit/delete/failure paths and reviewed visual baselines remain incomplete. Route rendering and alpha publication do not imply completion of the original sitewide acceptance matrix.

Verify artifacts last 14 days; release evidence lasts 30 days. Do not upload raw backend SQL logs, setup tokens or bearer tokens.
