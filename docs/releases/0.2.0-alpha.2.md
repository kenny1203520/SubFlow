## 執行指令

所有 shell 命令遵循專案 RTK 規範。Go 測試先於任何覆寫 embedded assets 的程序。先在 repository 根目錄確認候選 SHA，再依標示目錄執行。

```powershell
rtk git status --short --branch
rtk git rev-parse HEAD
```

在 `backend/` 執行：

```powershell
rtk go vet ./...
rtk go test ./...
```

在 `frontend/` 執行：

```powershell
rtk npm ci
rtk npm test -- --coverage
rtk npm run build
rtk npm run test:e2e
rtk npm audit --audit-level=high
```

回 repository 根目錄執行：

```powershell
rtk docker build -t subflow:0.2.0-alpha.2 .
```

`npm ci` 與 build 不代表整合容器已驗證；完整 smoke 必須對容器執行。現有 Verify 保存 UI 截圖 14 天，失敗時保存 report／trace／video；在 artifact 到期前整理發佈證據。

以下為驗收與發佈決策完成後的操作，**此計畫準備階段不執行**：

```powershell
rtk git switch release/0.2.0-alpha.2
rtk git status --short --branch
rtk git tag -a v0.2.0-alpha.2 -m "SubFlow 0.2.0-alpha.2"
rtk git push origin v0.2.0-alpha.2
```

Tag 必須指向已驗證且與遠端一致的候選提交。發佈後將 release 以 merge commit 合回 develop；不自動合入 master 或部署到正式環境。
