# 0.2.0-alpha.3 release qualification

Alpha 3 includes attachment dropzones and document previews, the ledger save-race repair and isolated browser CI. The source starts at develop `68c832e5da10dfb96b1620e4eab590f8d52cb89f`. Existing Alpha 1/2 tags and images remain unchanged.

## Integrated evidence

- [Develop CI](https://github.com/kenny1203520/SubFlow/actions/runs/39840900839): all nine jobs passed, including all five browser projects, backend/frontend verification, lints and production-container qualification.
- [CodeQL](https://github.com/kenny1203520/SubFlow/actions/runs/39840900546): passed on the same source.
- Browser suite: 75 tests, 15 per project. Chromium, Firefox and WebKit desktop plus Chromium and WebKit touch emulation passed. The PDF test renders real PDF pixels through a component harness; the draft test checks selection, no premature upload and cancellation against an isolated account.
- Frontend: 158 tests across 39 files; dependency audit reported zero vulnerabilities. Release metadata/publication contracts: 25 tests. Build passed with bundle-size/dynamic-import warnings.
- Backend: 426 tests in 14 packages; go vet passed. The attachment feature and save repair introduce no backend endpoint or schema changes; existing mutation/audit behavior is retained.
- The earlier Alpha 2 integration failure exposed a real save race. The regression holds an SSE-triggered background read and asserts a real PATCH succeeds while it remains pending. Unique fixture names and separate per-project backends prevent cascading matches from failed attempts.

## Publishing gates

The release PR and exact version tag must both pass reusable Verify, including every browser project. The tag additionally validates package/lock/changelog versions, qualifies fresh production-container setup/auth/version/audits and rehearses Alpha 1 upgrade/offline restore before publishing. Final outcome requires the expected image digest, GitHub pre-release and changelog, while stable latest remains unchanged.

This source record is preparation evidence, not a claim that publication has occurred. The tag workflow and its retained evidence are authoritative. After publication, merge the release branch back into develop; master remains on stable. Do not move an existing published tag.

## Limits

Office previews extract text/cells rather than reproduce original layout. Browser coverage does not yet include every Office upload-to-preview path, malformed/large file or PDF pagination permutation. The [coverage matrix](../../frontend/e2e/COVERAGE.md) identifies broader role, failure-path and visual-baseline gaps. Touch emulation is not physical-device testing.

Upgrade qualification uses disposable generated data, not a user's installation. Preserve the full PocketBase directory and settings encryption key before a real upgrade. Restore old backups into separate storage with their matching image.

Playwright artifacts last 14 days; tag release evidence lasts 30 days. Retain safe publication/container/upgrade JSON as release assets for durable evidence. Raw backend logs, tokens and secret URLs must not be uploaded.
