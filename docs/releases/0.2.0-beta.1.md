# SubFlow 0.2.0-beta.1 release qualification

This candidate is intended as a correction update after `0.2.0-beta`. It includes the account security work in this change and must pass the repository's required tests, browser checks, and CodeQL gates before publication. This document is not evidence that a tag, image, or release has been published.

## Included changes

- Add a system administrator switch for password reset. Existing initialized installations enable it during upgrade; new installations start with it off. The server accepts requests only when reset is enabled, PocketBase password authentication is enabled, the application URL is valid, and SMTP is configured.
- Add enumeration-resistant password recovery on `/auth` and let signed-in users request a reset for their account. Use PocketBase reset tokens and password policy. Already issued links remain valid until they expire even if the switch is later disabled.
- Allow OIDC and email OTP accounts to establish a local password through verified-email recovery when an administrator enables password reset.
- Allow verified sign-in email changes. Confirm with the current local password, invalidate the old session, and queue a security alert to the previous address with retry support.
- Preserve standalone email OTP. For accounts requiring MFA, request OTP only from a live password or OIDC challenge; apply the configured OTP CAPTCHA to first sends and resends.
- Put reset and email-change tokens in URL fragments, remove them from browser history before submission, and send them only in request bodies.
- Audit request, delivery, confirmation, CAPTCHA, throttling, and invalid or expired credential outcomes without writing secrets or full links into audit summaries.

## Beta testing focus

1. Upgrade a disposable copy of an initialized deployment and start a fresh installation. Verify the default switch values and call the PocketBase reset API directly with the switch on and off.
2. Configure a valid PocketBase Application URL, password authentication, and SMTP. Verify the UI hides the reset entry when prerequisites are unavailable and the backend still enforces them.
3. Exercise reset, email change, password/OIDC-to-OTP MFA, standalone OTP, CAPTCHA resends, expired links, duplicate concurrent confirmations, and session invalidation on desktop, mobile widths, and keyboard-only navigation.
4. Fail security-email delivery and confirm it appears in the administrator retry list and still targets the previous email address after an email change.
5. Review the test results, browser coverage, and CodeQL status before publishing. External SMTP delivery and real CAPTCHA provider behavior require non-production credentials and are not established by local tests.
