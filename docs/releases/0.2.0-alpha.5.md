# SubFlow 0.2.0-alpha.5 release qualification

Alpha 5 carries the dependency and security updates already merged into master onto the prerelease line. The release branch was created from `develop`, then synced with `master` so the candidate includes the merged Dependabot and CodeQL updates. `master` remains the stable line.

## Included changes

- Updated the Go/PocketBase, frontend and GitHub Actions dependencies to the versions already verified on master; action references remain pinned to immutable commit SHAs.
- Refreshed the frontend lockfile. `npm audit` reports no vulnerabilities after updating `serialize-javascript`.
- Added coverage proving the TIFF decoder rejects an out-of-range palette reference before PocketBase's imaging path can process it. The upstream imaging advisory has no patched release; this candidate uses the validated `golang.org/x/image` decoder and records the mitigation rather than claiming an upstream patch.
- Kept the stable Vue-generated form-control IDs and regression coverage for CodeQL's previous insecure-randomness findings.

## Verification

- Local `npm ci` completed and `npm audit` reports 0 vulnerabilities.
- Local `npm run test:ci` passed: 159 Vitest tests and both CodeQL language analyses completed successfully.
- Local `go vet ./...` passed; `go test ./...` passed 428 tests in 14 packages.
- Local frontend production build passed. ESLint reported 0 errors and 3 existing warnings.
- Release PR CI/CodeQL and the tag publication workflow remain authoritative for publication.

## Publishing gates

The release tag must validate package/lockfile/changelog versions, pass the reusable Verify workflow, qualify fresh production-container setup and registration, rehearse the Alpha 1 upgrade and restore, publish the image and GitHub prerelease, and verify the resulting image digest. Alpha prereleases must leave the stable `latest` image unchanged.

This document records the candidate and its preparation, not a claim that publication has succeeded. After the tag workflow succeeds, merge the release PR back into `develop`; leave `master` on stable.
