Frontend unit tests passed (158 tests across 39 files); Go tests passed across 14 packages (427 tests), and `go vet` passed.

## Publishing gates

The Alpha 4 release branch PR and exact version tag must pass reusable Verify, including every browser project. The tag additionally validates package/lock/changelog versions, qualifies fresh production-container setup/auth/version/audits and rehearses Alpha 1 upgrade/offline restore before publishing. The release workflow verifies the image digest, GitHub pre-release and changelog, and confirms stable `latest` remains unchanged.

This source record is preparation evidence, not a claim that publication has occurred. The tag workflow and its retained evidence are authoritative. After publication, merge the release branch back into develop; master remains on stable. Do not move an existing published tag.

## Limits

Browser coverage uses desktop engines and touch emulation, not physical devices. The full role, CRUD, failure-path and reviewed visual-baseline matrix remains incomplete. Office previews extract text/cells rather than reproduce original document layout; full upload-to-preview coverage for every Office format, malformed files and large documents remains incomplete. See the [coverage matrix](../../frontend/e2e/COVERAGE.md).

Upgrade qualification uses disposable generated data, not a user's installation. Preserve the full PocketBase directory and settings encryption key before a real upgrade. Restore old backups into separate storage with their matching image.

The release workflow retains Alpha 4 publication evidence for 30 days. Raw backend logs, tokens and secret URLs must not be uploaded.
